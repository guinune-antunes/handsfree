1 Visão Geral

O Discord Clone Leve é uma aplicação de comunicação em tempo real que replica as funcionalidades essenciais do Discord: chat de texto, canais de voz com áudio em tempo real, e compartilhamento de tela. É composto por 3 módulos independentes que trabalham juntos.

4 Fluxos Detalhados

4.1 Login e Validação de Conexão

sequenceDiagram participant U as Usuário participant R as React - LoginScreen participant T as Tauri - Rust participant FS as Filesystem participant S as LiveKit Server U->>R: Preenche Host, Porta, Nickname U->>R: Clica Conectar R->>T: invoke validate_connection host port T->>S: TcpStream connect_timeout 5s alt Conexão OK S-->>T: TCP handshake ✅ T-->>R: Ok Conectado R->>T: invoke save_config T->>FS: Salva config.json em AppData R->>R: setScreen dashboard else Falha S--xT: Timeout / Recusado T-->>R: Err mensagem R->>U: Exibe erro end
Detalhes técnicos:
  • O Rust usa TcpStream::connect_timeout com 5 segundos de timeout
  • A config é salva em %APPDATA%/discord-clone-leve/config.json
  • Na próxima abertura, load_config carrega automaticamente os valores salvos

4.3 Áudio em Tempo Real

sequenceDiagram participant A as Participante A - Microfone participant SDK_A as LiveKit SDK A participant SFU as LiveKit SFU - Servidor participant SDK_B as LiveKit SDK B participant B as Participante B - Alto-falante A->>SDK_A: getUserMedia audio SDK_A->>SFU: Publica Audio Track WebRTC Note over SFU: SFU recebe o stream e encaminha para todos os subscribers SFU->>SDK_B: Encaminha Audio Track SDK_B->>B: new Audio srcObject stream autoplay true Note over A,B: Fluxo contínuo de pacotes RTP Codec Opus 48kHz 32-64 kbps
Como o áudio funciona no código:
  1. Captura: setMicrophoneEnabled(true) → chama getUserMedia
  2. Envio: O SDK empacota o áudio em RTP e envia via WebRTC ao SFU
  3. Recepção: Evento TrackSubscribed → cria <audio> element programático
  4. Mute: setMicrophoneEnabled(false) → para de enviar pacotes
  5. Deafen: audioEl.muted = true em todos os elements remotos

7 Infraestrutura Docker

graph TB subgraph DOCKER["Docker Engine"] subgraph HOST_NET["network_mode host"] LK["livekit-server Portas 7880 7881 3478 UDP 50000-60000"] end subgraph BRIDGE["Bridge Network"] REDIS_C["redis 7-alpine Port 6379 Volume redis-data"] end end LK -->|"127.0.0.1:6379"| REDIS_C
Por que network_mode: host para o LiveKit?
  • O LiveKit precisa de acesso direto às interfaces de rede para WebRTC
  • UDP media streams precisam de portas dinâmicas (50000-60000)
  • Evita overhead de NAT do Docker bridge
  • Redis fica em bridge com port mapping porque só precisa de uma porta TCP
